# 合同修订 1（草案，未冻结）：Confirm01_JAG 的新数据改用 2020–2024 对 2020–2025

起草：2026-11-17 10:45 UTC。用户同意后去掉"草案"、记录 SHA-256，并在 CONTRACT_CN.md 的偏差记录中引用本文件。此前未读取任何新瓦片的数值（E15N10 的 2020–2025 版只做过结构检查，见 RUN_LOG_CN.md）。

## 1. 原因

- 2026-11-17 10:32 UTC，EGMS 存档只提供 2020-2024 与 2020-2025 两个版本，2019-2023 已不可下载（下载程序探测；用户确认）。合同 §2.1 规定的 N 集版本对（2019–2023 对 2020–2024）无法取得。
- 结构检查表明 2020-2025 版（日期 2020-12-09 至 2025-11-25）是窗口后移约一年的独立重处理：测点坐标部分不同，pid 不同，共有日期上 98.8% 的数值不同。因此 2020–2024 对 2020–2025 是一对新的相邻重处理版本，可用于确认。

## 2. 改动

### 2.1 版本对与数据集

- **原版本对 P1**：A = 2019–2023，B = 2020–2024。
- **新版本对 P2**：A′ = 2020–2024，B′ = 2020–2025。两版都取存档中 sub_release 最高的文件。
- 数据集变为三个：
  - **O**：136 个旧瓦片 × P1（不变，本机已有）；
  - **O′**：同样 136 个旧瓦片 × P2（新下载 2020–2025 版；2020–2024 版用本机已有文件。若存档中有更高 sub_release，则下载该版本并记录）；
  - **N′**：按原抽签顺序与配额得到的新瓦片 × P2。
- N′ 的跳过规则：存档中查不到 2020–2025 或 2020–2024 任一版本即跳过并记录；抽签顺序、配额、剔除与补抽规则不变。

### 2.2 第一部分（复现）

- **主判读在 N′ 上进行**，标准与合同 §4 第一部分完全相同（含 F6 的放宽档）。
- **O′ 作为对照**，同一套标准，只用于解释：
  - N′ 不复现而 O′ 复现：差异来自瓦片；
  - 两者都不复现：该发现依赖版本对，论文中写成"只在 P1 上观察到"。
- F4 与 F5 的冻结系数仍为 FROZEN_PARAMS.json（在 O × P1 上算得），不在 P2 上重算。这一检验比原合同更严：系数要跨版本对迁移。

### 2.3 第二部分（A）

- 在 O、O′、N′ 三个数据集上分别计算。
- 一致性判读（绝对差 ≤ 5 个百分点，或比值在 [2/3, 3/2]）改为对三组两两比较：
  - O 对 O′：同瓦片，不同版本对；
  - O′ 对 N′：同版本对，不同瓦片。
- 一个数字只有三组都一致时才写成结论；否则按"随版本对变化"或"随瓦片变化"写，并给出各组值。
- 方向性预期（公共窗口的不一致率低于按发布值的）须在三组上都成立才算成立。

### 2.4 第三部分（B）

- 主判读在 N′ 上，O′ 作对照；读法与门限不变。
- B2 抽稀的供体从 N′ 的稀疏与高山瓦片中按原规则抽取。

### 2.5 GNSS

- 站点的入选条件与拟合同 RelCons01，但在 P2 的公共窗口 W′ 内判定。
- 抽签用的候选规则（站点数据覆盖 2020-01-01 至 2023-12-31）只用于已冻结的分层，不变。
